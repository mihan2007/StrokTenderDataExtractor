# Перенос проекта на Mac (или любой другой компьютер) — чек-лист

## Что это вообще такое технически

Это не отдельная программа, которую можно просто "запустить" — это связка из трёх частей:

1. **`CLAUDE.md`** — большая инструкция (системный промпт) для Claude: пошаговый workflow анализа тендерной документации ("Тендер Заполняй").
2. **Python-скрипты в `tools/`** — механическая часть (распаковка архивов, конвертация ODF, сохранение в CSV/XML, отправка в NocoDB), которые Claude вызывает через bash по ходу выполнения инструкции.
3. **Папка проекта, подключённая к сессии Claude** (Cowork / Claude Desktop) — без этого подключения CLAUDE.md никто не читает и скрипты никто не запускает.

Аккаунт и API-ключи (DeepSeek, NocoDB) — **общие**, ничего не меняем и не перевыпускаем. Скрипты `nocodb_client.py` и `deepseek_extract.py` в любом случае выполняются в облачном окружении Claude, а не на компьютере пользователя — от ОС заказчика (Mac/Windows) они вообще не зависят.

## Проект теперь сам настраивается на новой машине — вручную почти ничего делать не нужно

Раньше в CLAUDE.md/PARTICIPATION.md/PREPARE_DOCS.md было 10 захардкоженных Windows-путей (`C:\Users\user\...`), которые пришлось бы редактировать руками при переносе на Mac. **Это исправлено:**

- Все ссылки на файлы/скрипты самого проекта (`tools/extract_archive.py`, `COMPANY.md`, `PARTICIPATION.md` и т.п.) теперь заданы как пути **относительно папки проекта**, а не абсолютным Windows-путём — Claude сам резолвит их через уже подключённую папку, независимо от того, где эта папка лежит на конкретном компьютере.
- Базовая папка тендеров (аналог `Строк\`) — не зависит от расположения проекта, поэтому для неё добавлен **Шаг 0** в CLAUDE.md и файл `tools/tender_base_folder.txt`:
  - При первом запуске на новой машине (или когда файла нет / путь в нём больше не существует) Claude **сам спросит** пользователя, где на этом компьютере лежат папки тендеров, и сохранит ответ в `tools/tender_base_folder.txt`.
  - На всех последующих сессиях, пока конфигурация валидна, Шаг 0 **полностью пропускается** — вопрос не повторяется и ничего не проверяется заново.
  - `tools/tender_base_folder.txt` добавлен в `.gitignore` — у каждой машины своё значение, при обновлении из git не перетирается и не попадает в репозиторий.
- Заодно тот же Шаг 0 при первом запуске выполняет **диагностику окружения** — новый скрипт `tools/env_check.py` (см. ниже) — тоже один раз, не при каждой обработке тендера.

Ваша текущая Windows-машина не пострадала: я сразу прописал в `tools/tender_base_folder.txt` актуальный путь (`C:\Users\user\Desktop\временно\Строк\`), так что для вас Шаг 0 при следующей сессии увидит валидную конфигурацию и молча пропустится — вопросов не будет, ничего не изменится в текущей работе.

## `tools/env_check.py` — диагностика окружения (одинаково для Mac/Windows/Linux)

Новый скрипт, который проверяет не просто "файл существует", а реально ли компонент запускается на этой машине:

- Python 3 (версия);
- unrar — через ту же логику, что и в `extract_archive.py` (теперь она реально пробует запустить найденный бинарник, а не просто проверяет флаг "исполняемый", см. ниже);
- LibreOffice/`soffice` — аналогично, через логику из `convert_odf.py`;
- Python-пакеты `openpyxl`, `rarfile`, `py7zr` (последние два ставятся сами при первом использовании — если их нет, это не считается проблемой).

Результат — JSON, и для каждого отсутствующего компонента — готовая команда установки **под определённую скриптом ОС** (например, для Mac — `brew install unrar`, `brew install --cask libreoffice`; для Windows/Linux — свои варианты). Claude показывает эти команды пользователю на Шаге 0, если что-то не найдено, но не блокирует работу — то, что не завязано на отсутствующий компонент, продолжает работать.

Можно запустить и вручную в любой момент: `python3 tools/env_check.py`.

## Что уже поправлено в коде (помимо путей и диагностики)

- **`tools/extract_archive.py`** — `find_unrar_tool()` теперь реально запускает найденный unrar перед тем, как его принять. Раньше на Mac скрипт молча пытался бы выполнить Linux-бинарник `tools/bin/unrar` (он в проекте — под x86-64 Linux) и падал бы с ошибкой; теперь в этом случае сам переключается на системный unrar.
- **`tools/convert_odf.py`** — `find_soffice()` дополнительно проверяет стандартный путь установки LibreOffice на Mac (`/Applications/LibreOffice.app/Contents/MacOS/soffice`).

Оба изменения обратно совместимы — на Windows поведение не изменилось.

## Что по-прежнему нужно поставить на Mac руками (софт есть только в системе, не в проекте)

1. **Claude Desktop** — тот же общий аккаунт.
2. **Python 3** — `brew install python3`.
3. **unrar** — `brew install unrar` (иначе `.rar`-архивы распаковать будет нечем — увидите это сразу в отчёте `env_check.py`).
4. **LibreOffice** — `brew install --cask libreoffice` (нужен только для `.odt/.ods/.odp`; без него всё остальное работает).

## Перенос файлов

- Скопировать всю папку `StrokTenderDataExtractor` целиком (AirDrop / флешка / облако) **вместе с `secrets/`** — ключи общие, менять не нужно. `tools/tender_base_folder.txt` можно смело копировать тоже (или не копировать вовсе) — Шаг 0 сам определит по нему (и по факту, существует ли записанный там путь на новой машине), нужно ли спрашивать заново.
- `.git` можно не переносить, если история/синхронизация с GitHub (`mihan2007/StrokTenderDataExtractor`) не нужна заказчику.
- Расположение на диске — любое, специально ничего прописывать не нужно (см. выше).

## Подключение в Claude Desktop на Mac

- Войти под тем же общим аккаунтом.
- Подключить папку проекта к сессии/задаче в Cowork — так же, как сейчас на Windows.
- CLAUDE.md Claude подхватывает сам, как только папка подключена как локальный проект.

## Проверка после переноса

- Первое сообщение Claude в новой сессии на Mac — ожидаем, что он спросит про базовую папку тендеров (Шаг 0) и покажет результат `env_check.py`. Если он этого не сделал (например, случайно скопировался старый `tools/tender_base_folder.txt` с реально существующим на Mac путём) — можно попросить явно: «перепроверь окружение и базовую папку».
- Прогнать через Шаги 1–5 тестовую папку (например, уже есть `_test_entry/`, `_test_entry2/`) — убедиться, что `.docx/.pdf/.xlsx` читаются.
- Распаковать тестовый `.zip` и, если есть, `.rar`.
- Шаг 5.2 (DeepSeek) и Шаг 7.1 (NocoDB) отдельно тестировать не нужно — выполняются в облаке, от компьютера заказчика не зависят.
