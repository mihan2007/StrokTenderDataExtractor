# StrokTenderDataExtractor

AI-пайплайн для автоматизации работы с тендерной документацией (44-ФЗ / 223-ФЗ): извлечение структурированных данных из закупочных пакетов, кросс-проверка вторым ИИ, синхронизация с базой данных и подготовка документов заявки.

Построен как экспертная роль («Тендер Заполняй») поверх Claude Code — вся логика описана в системном промпте (`CLAUDE.md`), а механическая часть (сборка XML, нормализация чисел, работа с API) вынесена в отдельные Python-скрипты.

## Проблема

Тендерный пакет — это обычно 5–15 документов (извещение, документация, техзадание, проект договора, приложения, спецификации), в PDF/DOCX/XLSX, часто в архиве. Нужные данные разбросаны по файлам, ссылаются друг на друга («см. приложение №3»), а конкретные цифры и даты — самое дорогое место для ошибки. Ручной разбор одного тендера занимает от 30 минут до нескольких часов.

## Что делает инструмент

- **Извлекает 25+ полей** из документации закупки в 7 структурированных блоков: товар и поставка, цена и условия оплаты, обеспечение, ключевые даты, организатор/заказчик, площадка и процедура, национальный режим (ПП РФ №1875).
- **Разворачивает архивы** (`.zip`, `.rar`, `.7z`, `.tar.gz`) и конвертирует документы LibreOffice/OpenDocument (`.odt/.ods/.odp`) автоматически, без ручной работы.
- **Разрешает внутренние ссылки** — если в проекте договора написано «см. спецификацию», инструмент сам находит нужный файл среди документов пакета и подставляет реальное значение вместо голой отсылки.
- **Строит таблицу позиций и цен**: по каждой позиции — количество, НМЦК, рыночная цена аналога (веб-поиск по марке/модели или по техническим характеристикам), размеры упаковки, источник.
- **Сверяет состав закупки** между несколькими источниками документации (техзадание, форма коммерческого предложения, спецификация к договору) и явно помечает расхождения в количестве/номенклатуре.
- **Кросс-проверяет критичные поля вторым независимым ИИ** (DeepSeek) — цену, даты, срок оплаты, срок поставки — до показа результата пользователю. Совпадения и расхождения помечаются маркерами (`✅` / `🔺`), спорные места перепроверяются по первоисточнику.
- **Определяет тип процедуры** по формальным признакам, когда заказчик не назвал его явно, по отдельному классификатору (запрос котировок, конкурс, редукцион, БРИФ и др.).
- **Присваивает внутренний номер** тендера для собственного учёта, с автоинкрементом и идемпотентным переиспользованием при повторном сохранении.
- **Сохраняет результат** в XML, PDF-отчёте и сводном CSV-реестре — при повторной обработке того же тендера запись обновляется, а не дублируется.
- **Синхронизируется с NocoDB**: основная запись в реестре + отдельная таблица-спецификация по позициям на каждый тендер, с типизированными колонками, автоконвертацией валют по курсу ЦБ РФ и цветовыми маркерами срока оплаты.

## Как это устроено

```
Документы тендера (папка)
        │
        ▼
  Сканирование + распаковка архивов / конвертация ODF
        │
        ▼
  Извлечение 7 блоков данных (docx/pdf/xlsx skills)
        │
        ├──► Таблица позиций и цен + веб-поиск рыночных цен
        ├──► Сверка позиций между источниками
        └──► Кросс-проверка критичных полей вторым ИИ (DeepSeek)
        │
        ▼
  Подтверждение пользователем
        │
        ▼
  Сохранение: XML + PDF + CSV-реестр  ──►  Синхронизация с NocoDB
```

## Технологии

- **Claude / Claude Code** — оркестрация пайплайна, чтение документов (skills `docx`/`pdf`/`xlsx`), рассуждение над данными
- **Python 3** — служебные скрипты: сборка XML, нормализация данных, работа с архивами, HTTP-клиенты
- **DeepSeek API** — независимая кросс-проверка критичных полей
- **NocoDB API** — облачная база данных реестра закупок
- **LibreOffice (headless)** — конвертация ODF-документов

## Структура репозитория

```
CLAUDE.md               — основной системный промпт (роль, пошаговый workflow)
FIELDS_REFERENCE.md      — где хранится/редактируется каждое поле (XML-тег, CSV, NocoDB)
PROCUREMENT_TYPES.md     — методика классификации типа процедуры закупки
PARTICIPATION.md         — workflow подготовки заявки на участие
PREPARE_DOCS.md          — подготовка комплекта документов участника
tools/
  save_tender.py         — сборка XML/PDF/CSV, нормализация чисел, внутренняя нумерация
  nocodb_client.py        — синхронизация с NocoDB (реестр + таблицы спецификаций)
  deepseek_extract.py     — кросс-проверка критичных полей вторым ИИ
  extract_archive.py      — распаковка zip/rar/7z/tar с защитой от zip-slip
  convert_odf.py           — конвертация LibreOffice/OpenDocument → OOXML
  env_check.py            — диагностика окружения (Python/unrar/LibreOffice)
secrets/                  — API-ключи (в .gitignore, в репозиторий не входит)
```

## Точность и ограничения

- Извлечение полей — на базе LLM-анализа документов, не формальный парсер: точность порядка 80% на неоднородных реальных пакетах документов (скан-PDF, нестандартная вёрстка).
- Кросс-проверка вторым ИИ снижает риск пропуска ошибки в критичных числовых/датных полях, но не заменяет финальную проверку человеком перед подачей заявки.
- Веб-поиск рыночных цен и аналогов — вспомогательный ориентир для оценки, не заменяет реальный запрос коммерческих предложений.
- Инструмент рассчитан на запуск через Claude Code (нужен доступ к skills `docx`/`pdf`/`xlsx` и веб-поиску); часть шагов (запросы к DeepSeek/NocoDB) требует сетевого доступа к внешним API.

## Установка и настройка

1. Клонировать репозиторий, создать папку `secrets/` и положить туда собственные API-ключи (`API_key_DeepSeek.txt`, `API_key_NocoDB.txt`) — папка уже в `.gitignore`.
2. При первом запуске на новой машине указать базовую папку с тендерами — путь сохраняется в `tools/tender_base_folder.txt`.
3. Настроить собственную базу NocoDB (структура таблицы описана в `FIELDS_REFERENCE.md`) и указать её `base_id`/`table_id` в `tools/nocodb_client.py`.
4. Запускать через Claude Code с подключённой папкой проекта — дальнейший workflow описан в `CLAUDE.md`.
